# node-image-steam (image-steam)

A realtime image manipulation web server built on Node.js and [sharp](https://sharp.pixelplumbing.com/). Images are fetched from configurable storage backends, processed on demand via URL "steps" (e.g. `/img.jpg/:/rs=w:640/cr=l:5,t:5,w:90,h:90`), and cached.

As of v1.0.0 the entire codebase is TypeScript (ESM) and runs on **both Node.js (>=24) and Bun**, on Windows/macOS/Linux.

## Runtime model: type stripping, no build step for dev

- Source is executed directly as `.ts` via Node's native type stripping (Node 24+) or Bun. There is **no transpile step** for dev/test.
- TypeScript must remain *erasable*: `erasableSyntaxOnly` is enforced — no enums, no namespaces, no parameter properties.
- Relative imports use explicit `.ts` extensions (`allowImportingTsExtensions` + `rewriteRelativeImportExtensions`). The published package is compiled to `dist/` via `tsconfig.build.json` (`npm run build`, run automatically on `prepack`), which rewrites `.ts` imports to `.js`.
- `import.meta.dirname` replaces `__dirname`. Use `process.execPath` when spawning child processes so the active runtime (Node or Bun) is reused.
- Node refuses to type-strip inside `node_modules`; workspace packages are fine because their symlinks resolve to real paths under `packages/`.
- `strict` is off; liberal `any` is acceptable (codebase converted from untyped JS).

## Layout

- `lib/` — library source (published as `dist/`): `http/`, `router/`, `processor/`, `storage/` (fs, http, s3, isteamb, …), `security/`, `helpers/`, `image.ts`, `index.ts`
- `test/` — mocha tests (`*.tests.ts`), in-process; `test/files/` fixture images
- `scripts/` — dev server (`server.ts`), dev config (`dev.ts`), yargs patcher, hash benchmark
- `bin/` — published CLI entries (`isteam.js`, `isteamd.js` — plain ESM wrappers around `dist/`)
- `packages/image-steam-bench/` — workspace package: load-testing/benchmark TUI (blessed), spawns worker threads (`src/test/*.ts`) against a running isteam server

## Commands

- `npm start` / `npm run start:bun` — dev server on :13337 + demo browser launch (`nodemo` / `nodemo:bun` skip the browser)
- `npm test` — full pipeline: prettier --write → typecheck (tsc) → c8 + mocha → coverage reports → threshold check → `npm outdated` (informational)
- `npm run unit` — just c8 + mocha
- `npm run build` — emit `dist/` (build must stay clean; CI/publish depend on it)
- `npm run bench` / `bench:bun` — run image-steam-bench against localhost:13337 (start the server first). Scores are appended to `isteamb.log`, so non-interactive runs still capture results.

## Critical invariants

- **xxHash32 seed `0xabcd1133` must NEVER change** — it determines cache keys for every deployment's cached artifacts. Pinned-value tests live in `test/image-steps.tests.ts`.
- `lib/helpers/xxhash.ts` resolves the hasher at startup (top-level await): `Bun.hash.xxHash32` (Bun) → `xxhash-wasm` (everything else). Both return identical unsigned 32-bit values; keep it that way.
- ETag snapshot file `test/image-server.etags.json` is auto-regenerated by an `after()` hook. A sharp upgrade can legitimately change etags: first `npm test` run fails on the changed entries and rewrites the file, second run passes. Review the diff before committing.
- Some tests are skipped in CI via `IS_CI_ENV` (avif and high-sigma blur in `test/image-server.requests.ts`).

## Node 26 yargs gotcha (do not remove `scripts/fix-yargs-node26.ts`)

Node >=26 treats extensionless files inside a `"type": "module"` package as ESM **even when require()d**. yargs 16/17 ship an extensionless CJS file `yargs` with an exports map pointing `require` at it, so `require('yargs/yargs')` crashes (used by c8). `scripts/fix-yargs-node26.ts` runs on `prepare` (every `npm install`) and patches every installed copy of yargs: copies `yargs` → `yargs.cjs` and rewrites `exports['./yargs']`. No Node CLI flag fixes this; yargs 18 drops the CJS entry entirely (unusable for c8). If c8/mocha ever fail with `require is not defined in ES module scope`, re-run `npm install` or `node scripts/fix-yargs-node26.ts`.

## Testing notes

- mocha 11 + c8 11 (older majors break on Node 26). Config: `.mocharc.json` (spec `test/**/*.tests.ts`), `.c8rc.json` (`include: lib/**` — this scopes both report and check-coverage).
- Tests run in-process against `isteam.http.start()` on port 13337; `test/security.tests.ts` mutates the shared config singleton imported from `test/image-server.config.ts` (ESM module cache makes this work).
- Coverage thresholds: statements 70, functions 75, branches 50, lines 70.
- chai 4 / sinon 14 / sinon-chai 3 are intentionally pinned (newer majors are ESM-only/breaking with current patterns).

## Style

- prettier 2.8.8 formats `lib test scripts` on every `npm test` (also check `packages/image-steam-bench` manually when editing it).
- Default exports are the norm; preserve existing behavior faithfully when refactoring — several long-standing quirks are load-bearing for cache compatibility.
